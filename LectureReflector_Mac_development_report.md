## 1. Summary

LectureReflector records a lecturer delivering a lecture — webcam and microphone — composited live with their presentation slides into a single MP4 file, and automatically generates a transcript. The lecturer presents normally from PowerPoint, Keynote, or a reveal.js/Quarto deck in a browser; LectureReflector captures that *window* directly, so the recording never shows notifications, other windows, or the desktop, and keeps recording even when the slides are behind other windows.

The project started from a Gemini-produced browser prototype (`gemini-code-1783873201727.html`) and its report. Per the project decision, the Mac app was rebuilt natively in Swift/SwiftUI, which eliminated the prototype's three structural weaknesses: unreliable MP4 support in browser `MediaRecorder`, no transcript path, and losing the entire lecture if the browser crashed. A Windows version is planned as an Electron app that reuses the prototype's canvas-compositing approach (spec milestone 4).

## 2. What was built

### Outputs per recording session

A folder named `LectureReflector <title> <date time>` containing:

| File | Contents |
|---|---|
| `lecture.mp4` | H.264 + AAC, 1280×720 (1600×720 in Sidebar layout), 30 fps |
| `lecture.txt` | Plain transcript |
| `lecture.srt` | Subtitles with timestamps — loadable as captions in any player or LMS |
| `chapters.txt` | Automatically detected slide-change timestamps |

### Features

- **Six live-switchable layouts:** Rectangle PiP (340×255), Circle PiP (240 px with white ring), Sidebar (1600×720 wide frame; slides keep full size beside a 320×720 lecturer panel), Floating Torso (on-device person segmentation cuts the lecturer out of their background and overlays the silhouette on the slides), Slides Only, and Camera Only. Layouts switch instantly during recording without interrupting the stream.
- **Crash-safe recording.** Capture is written as a fragmented QuickTime file (5-second fragments): a crash or power loss loses at most a few seconds, and the partial file remains playable. On Stop, the file is remuxed — not re-encoded — into the final MP4 in seconds.
- **Pause/resume** with a gapless timeline (paused time is excised from both audio and video timestamps).
- **Automatic slide-change chapters.** Twice a second while recording, the slide stream is compared with its previous state on the GPU; significant changes are logged as chapter timestamps.
- **On-device Whisper transcription** (WhisperKit / Core ML). Free, offline after the first model download, and private — lecture audio never leaves the Mac. Model selectable in Settings (`base`, `small`, `medium`, `large-v3`).
- **Recording aids:** live composited preview, mic level meter, optional 3-second countdown, camera mirroring option, elapsed-time display, and sleep/App Nap suppression while recording.
- **App icon:** original artwork — a full moon reflected in still water (明镜止水) — generated programmatically by `Design/makeicon.swift` (CoreGraphics), so it can be re-rendered or restyled by editing the script.

## 3. Architecture

Native Swift/SwiftUI app, macOS 14+, one dependency (WhisperKit, via Swift Package Manager). The Xcode project is generated by XcodeGen from `project.yml`.

```
ScreenCaptureKit (slide window)      AVCaptureSession (camera + mic)
        │ latest frame                       │ latest frame        │ audio buffers
        ▼                                    ▼                     │
   Compositor — Core Image / Metal, 30 fps timer, 6 layouts        │
        ▼                                                          ▼
   Recorder — AVAssetWriter, hardware H.264 + AAC, fragmented .mov
        ▼ on stop
   Passthrough remux → lecture.mp4 → WhisperKit → lecture.txt / .srt
```

Key design decisions:

1. **Timer-driven compositing.** ScreenCaptureKit only delivers frames when window content *changes*, and slides sit static for minutes. A 30 fps timer composites the latest slide and camera frames on the host clock, so output cadence never depends on slide activity, and audio (also host-clock-stamped) stays in sync.
2. **Window capture, not display capture.** The chosen window is captured at up to 2× resolution even while projected or occluded. Nothing else on screen can leak into the recording.
3. **Fragmented `.mov` first, MP4 second.** MP4 cannot be written crash-tolerantly by AVAssetWriter; QuickTime fragments can. The passthrough remux to MP4 costs seconds and no quality.
4. **Canvas size freezes at record start** (an MP4 video track cannot change dimensions mid-file). All layouts render adaptively into whichever canvas is active, so switching remains legal mid-recording — e.g., choosing Sidebar *before* recording gives the full 1600×720 frame.
5. **Vision instead of MediaPipe** for the Floating Torso layout — `VNGeneratePersonSegmentationRequest` is built into macOS, hardware-accelerated, and needs no bundled ML runtime. Segmentation runs on alternating frames with mask reuse to halve inference cost.

## 4. Verification status

- The app builds clean (no warnings) with Xcode 26.6, launches, and is signed with the developer's Apple Development certificate; the full record → MP4 → transcript flow compiles against real APIs end to end.
- Resolved during bring-up: iCloud-synced Desktop breaking codesign (derived data moved to `~/Library/Caches/LectureReflectorBuild`) and silent screen-capture denial from stale TCC entries left by earlier ad-hoc signatures (cleared with `tccutil reset`; prevented permanently by stable certificate signing).
- **Not yet exercised by a human:** an actual lecture recording. Recommended first test: a 2-minute run with real slides — check A/V sync, layout switching mid-recording, pause/resume, and that all four output files appear. First transcription downloads the Whisper model (~150 MB for `base`), so it needs network once.

## 5. Known limitations (v0.1)

- Chapters are written to `chapters.txt`, not embedded as an MP4 chapter track. Detection is threshold-based; progressive bullet reveals may or may not register as chapters depending on how much of the slide changes.
- Slide window must not be *minimized* (occluded or full-screen is fine). If the window closes mid-recording, the video continues with the last slide frozen. (v0.2.0: capture now follows a deck into its full-screen window, and *Entire screen* is available as a fallback.)
- Signed with the developer's "Apple Development" certificate (team `YCTW9YH58J`), so permission grants persist across rebuilds. A stale TCC entry (from the earlier ad-hoc-signed builds) can cause silent screen-capture denial; `tccutil reset ScreenCapture com.kevinmiller.lecture_reflector` clears it.
- Audio drift over very long sessions (multi-hour) is theoretically possible since mic timestamps come from the capture device clock while video uses the host clock; not expected to matter for typical lectures.
- Transcription time scales with model choice: `base` ≈ 2–6 min per lecture-hour on Apple Silicon; `large-v3` is much slower and downloads ~3 GB.
- The project folder lives on the iCloud-synced Desktop; build products must be kept outside it (`-derivedDataPath ~/Library/Caches/LectureReflectorBuild`) or codesign fails on File Provider extended attributes (“resource fork … detritus not allowed”). Documented in the README.
