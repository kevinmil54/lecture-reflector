# LectureReflector — Lecture Recording App: Specification

**A product of Kevin Miller and Timely Snow LLC (timelysnow.com)**

**Platforms:** macOS first (native Swift/SwiftUI). Windows later via Electron, reusing the browser-canvas compositing approach from the Gemini prototype (`gemini-code-1783873201727.html`).

## 1. What LectureReflector does

LectureReflector records a lecturer delivering a lecture and produces a single, self-contained video in which the presentation slides and the lecturer are composited together, plus a transcript. The lecturer presents normally — PowerPoint, Keynote, or a reveal.js/Quarto deck in a browser — and LectureReflector captures that window directly, so the projected/live view is never obscured and no notifications or other windows ever appear in the recording.

**Outputs per session** (saved to a user-chosen folder, named `LectureReflector <lecture title> <yyyy-MM-dd HHmm>`):
- `lecture.mp4` — H.264 + AAC MP4, 1280×720 (or 1600×720 in sidebar layout) @ 30 fps
- `lecture.txt` — plain transcript
- `lecture.srt` — subtitle file with timestamps (usable as captions on any player / LMS)

## 2. Architecture (macOS)

Single SwiftUI app target, macOS 14+, generated by XcodeGen from `project.yml` (same workflow as Babatalk: `xcodegen generate`, never hand-edit the .xcodeproj; build with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`).

```
┌─────────────┐  ┌──────────────┐
│ SCStream    │  │ AVCapture     │   slides window   camera + mic
│ (slides)    │  │ Session       │
└──────┬──────┘  └──────┬───────┘
       │ latest frame    │ latest frame        mic CMSampleBuffers
       ▼                 ▼                            │
   ┌────────────────────────────┐                     │
   │ Compositor (Core Image /   │  30 fps timer       │
   │ Metal, pixel-buffer pool)  │                     │
   └──────────────┬─────────────┘                     │
                  ▼                                   ▼
          ┌──────────────────────────────────────────────┐
          │ AVAssetWriter → lecture.mp4 (HW H.264 + AAC) │
          └──────────────────────┬───────────────────────┘
                                 ▼ (post-recording)
                      WhisperKit → lecture.txt / lecture.srt
```

### Modules
| Module | Responsibility | Key APIs |
|---|---|---|
| `SlideCapture` | Enumerate windows, capture the chosen slide window | ScreenCaptureKit (`SCShareableContent`, `SCStream`) |
| `CameraCapture` | Webcam video + microphone audio | `AVCaptureSession`, video/audio data outputs |
| `Compositor` | Merge latest slide + camera frames per layout at 30 fps on the host clock | Core Image (Metal-backed `CIContext`), `CVPixelBufferPool` |
| `Recorder` | Encode & write MP4; crash-tolerant | `AVAssetWriter` (H.264 hardware, AAC) |
| `Transcriber` | Post-recording transcription | WhisperKit (SPM; on-device Whisper via Core ML) |
| `RecordingSession` | State machine wiring the above; owns timestamps | — |
| UI (SwiftUI) | Source pickers, live preview, layout switcher, record controls, transcription progress | — |

### Design decisions
- **Timer-driven compositing, not frame-driven.** SCStream only delivers frames when the window content *changes* — slides are static for minutes at a time. A 30 fps timer composites the *latest* slide and camera buffers, so output cadence never depends on slide activity. All video timestamps come from the host clock; mic sample buffers (also host-clock) pass straight through, keeping A/V in sync.
- **Window capture, not display capture.** The lecturer picks the PowerPoint/Keynote/browser window; LectureReflector records it at up to native resolution even while it's projected, minimized behind other windows is not required — the window must be on screen (ScreenCaptureKit captures occluded windows fine, but not minimized ones).
- **Direct-to-MP4 with periodic session start.** Hardware H.264 via AVAssetWriter. Crash tolerance (milestone 2): write fragmented output or sidecar-chunk so a crash loses ≤ a few seconds.
- **On-device Whisper (WhisperKit).** Free, offline, private — lecture audio (including student questions) never leaves the Mac. Default model `base`; user-selectable up to `large-v3` in Settings. Model downloads once from Hugging Face on first transcription. (A cloud-API option can be added later behind the same `Transcriber` protocol.)

## 3. Layouts (from the Gemini spec)

Switchable live during recording without interrupting the stream. All implemented in v0.1:

1. **Rectangle PiP** — slides full-frame 1280×720; camera 340×255 bottom-right with white border.
2. **Circle PiP** — 240×240 circular mask with white ring.
3. **Sidebar** — canvas becomes 1600×720; slides full-size at left, camera in a 320×720 dark panel at right. The canvas size freezes at record start (an MP4 track can't change dimensions), so Sidebar must be selected before recording to get the wide frame; every layout renders adaptively into whichever canvas is frozen, so switching stays legal mid-recording.
4. **Floating Torso** — person segmentation (Vision `VNGeneratePersonSegmentationRequest`, alternating frames with mask reuse — no MediaPipe needed on macOS) overlays the lecturer's silhouette directly on the slides; falls back to Rectangle PiP if segmentation yields no mask.
5. **Slides only / Camera only** — momentary toggles.

## 4. Slide-source guidance (not code, workflow)

- **PowerPoint:** use *Slide Show ▸ Set Up Show ▸ Browsed by an individual (window)* or capture the presenter's slide window; LectureReflector captures any window, full-screen shows included (a full-screen show is still a window to ScreenCaptureKit).
- **Keynote:** *Play Slideshow in Window* (Keynote 12+) or full-screen play.
- **reveal.js / Quarto:** present in any browser window/tab; capture that window.
- Milestone 2: detect slide changes by frame differencing on the slide stream → chapter markers embedded in the MP4 and section breaks in the transcript.

## 5. Permissions & entitlements

- TCC: Screen Recording, Camera, Microphone (`NSCameraUsageDescription`, `NSMicrophoneUsageDescription`).
- App Sandbox: `com.apple.security.device.camera`, `.audio-input`, `.files.user-selected.read-write`, network client (WhisperKit model download).
- Bundle ID: `com.kevinmiller.lecture_reflector`.

## 7. Risks / notes

- MP4 + AVAssetWriter loses everything on hard crash until milestone 2's fragmenting — acceptable for MVP, flagged prominently.
- WhisperKit first-run model download requires network; transcription of a 60-min lecture with `base` takes ~2–6 min on Apple Silicon.
- Full-screen Keynote on a single-display Mac hides the LectureReflector UI; recommend two displays or windowed play. Recording continues regardless.
